# 用户提供的 V7 产品规格原文

高等数学 AI 学习工作台V7 完整开发、视觉理解与长期维护最高指令

Calculus Workbench · 可分发 Windows 本地软件 · DeepSeek 多模态 · 持续更新

本指令替代此前 V6 的“首版明确不做”限制。V7 按完整产品规划设计：首版优先完成核心闭环，但 OCR/视觉理解、联网研究、AI 出题与独立验题、期末 Word/PDF、长期维护和持续升级均属于正式路线，不再从产品需求中删除。

一、产品最高目标

开发一套真正可长期使用的中文高等数学 AI 学习软件，而不是 Demo、笔记壳或聊天页面。用户可导入自己的教材，系统建立可信教材底座，

再利用 DeepSeek 生成足够深入的个性化教辅，并通过课堂转写、错题、AI 对话和复测持续形成个人学习画像。

最终标准：即使学生一学期几乎没有听课，也应能够从第一章开始，依靠知识页与 AI Tutor 逐步真正理解课程。

二、核心技术架构

使用 TypeScript、React、Vite、Express 和 SQLite。优先使用当前 Node.js 内置 SQLite 能力。PDF.js 负责 PDF 显示、文字提取和页面渲染；

KaTeX 负责数学公式。服务仅监听 127.0.0.1，前后端同源，写接口校验来源与会话令牌。程序、数据、配置、日志、更新和备份必须分离，

全部使用相对路径，使整个软件目录移动磁盘后仍可工作。

三、多教材 Workspace

每本教材建立独立 Workspace，保存原 PDF、文件哈希、教材 ID、候选事实、已核验事实、AI 教辅、课堂转写、错题、学习证据、

对话、练习、诊断和个人复习资料。重复导入相同 PDF 时提示打开已有 Workspace，不覆盖学习数据；不同教材建立新 Workspace。

四、PDF 文本 + DeepSeek Vision 双通道教材理解

不要把教材理解限制为 PDF 文本抽取。系统采用双通道：

A. PDF.js 能可靠提取文字时，优先使用结构化文本；

B. 扫描页、复杂公式、图像、坐标图、版式混乱、跨栏、文本抽取失败或置信度低时，将相关 PDF 页面渲染成高质量图片，调用支持视觉输入的 DeepSeek 模型辅助识别和理解。

视觉模型应能辅助：读取扫描文字、识别数学表达式、理解函数图像/几何图、区分标题与正文、判断定义/定理/例题区域、理解复杂排版，

并将视觉结果与 PDF 文本结果交叉比较。视觉结果只能进入候选层，不能因为“模型看懂了”就直接成为 Ground Truth。

模型能力不得硬编码到单一旧模型名。Provider 设置需要独立配置 Text Model 与 Vision Model。当前官方视觉能力可使用 deepseek-flash，

但实现必须允许未来更换模型。图片可根据 Provider 能力采用 Base64、URL 或 Files API。发送教材页面到外部模型前应向用户说明数据类别。

五、传统 OCR 作为可选辅助，而非唯一方案

V7 允许加入 OCR，但 OCR 只是候选提取工具。对于扫描教材，可采用“页面图像 → OCR/视觉理解 → 文本与公式候选 → AI 结构分析 → 人工/规则核验”。

OCR、视觉模型和 PDF.js 三者出现冲突时不得静默选一个结果；关键数学内容必须进入核验流程。

六、可信教材 Ground Truth

自动识别章、节、定义、定理、推论、公式、证明、例题、习题、符号和知识依赖。任何自动识别结果首先是 EXTRACTED/NEEDS_VERIFY。

用户确认后才能成为 VERIFIED。AI 无权直接覆盖 VERIFIED 教材事实，所有修改保留版本历史。

不再强制把“准确第几页/精确区域”作为可信性的核心。来源优先使用教材 ID、章节、知识点 ID、原文片段、前后文锚点和内部 PDF 页索引（若可靠）。

能准确跳转就跳转；不能准确跳转就打开相关位置/章节并展示原文锚点，绝不能伪造精确页码。

七、DeepSeek 教学大脑

每次生成教学内容前必须检索：相关 VERIFIED 教材事实、必要前置知识、用户错题、历史卡点和有效学习解释。

标准链路：定位知识点 → 检索可信事实 → 检索前置知识 → 检索个人证据 → 生成 → 独立 Reviewer → 引用检查 → 公式检查 → 发布/待修订。

API Key 默认仅保存在服务内存，不进入数据库、日志、导出、备份或发行包。

八、真正的零基础深度教辅

知识页不能靠字数或栏目数量验收。适用时应讲清：前置知识、学习目标、概念为什么出现、直觉、严格定义、符号逐项解释、条件必要性、

反例、定理、证明目标、证明策略、为什么选择该方法、严格证明、隐藏步骤、基础例子、标准例题、每一步为什么、变式、边界情况、

常见错误、题型识别、前后联系、课堂补充、个人易错和理解检测。

Reviewer 固定问：假设学生从未学过这一节，仅凭当前页面和 Tutor，能否理解并完成一道基础题？

“显然、易得、同理、取某值即可”等初学者可能断层的位置必须展开。

九、上下文 AI Tutor 与“这里没懂”

用户可选中一句话、公式、证明步骤或例题步骤追问。Tutor 应判断卡点属于符号、定义、条件、证明逻辑、方法选择、计算还是前置知识缺失。

连续追问时必须改变教学策略，可在严格表述、直觉类比、具体数字例子、逐符号展开、逐步证明和前置补课之间切换，而不是反复改写同一句话。

十、个人学习闭环

持续吸收三类主要数据：课堂录音转写文本、错题、用户与 AI 的学习对话。原始内容永久独立保存，派生内容单独保存。

课堂内容提取老师强调、补充解释、方法和考试提醒；错题记录原题、用户步骤、错误位置、根因、知识点和复测；对话提取卡点、

无效解释、最终有效解释和前置缺口。

十一、有证据的弱点诊断

至少从概念、符号/定义、定理条件、计算、方法选择、证明/推理、综合应用、稳定性与长期保持等维度诊断。

每项弱点必须能展示证据；证据不足显示“待评估”。系统给出的补救必须具体到知识点、解释类型、训练数量、难度、复测时间和通过标准。

十二、AI 自动出题与独立验题（正式路线）

允许系统根据 VERIFIED 教材范围、用户弱点和权威外部资料生成原创练习，但 Generator 不能自己验证自己。

采用 Generator → 独立 Solver → Critic/Validator → 条件检查 → 答案检查 → 歧义检查 → 难度/范围检查 → 发布。

无法独立验证、存在歧义、条件不足、超出教材范围或答案冲突的题目必须丢弃或进入人工确认。

十三、联网研究（正式路线）

系统可联网研究新的题型、教学解释和公开课程资料，但外部内容进入 Research Sandbox，不直接污染 Ground Truth。

来源优先级：官方课程/考试材料、大学公开课程、出版社/开放教材、可靠教育机构。论坛和社区只能作为线索。

保存来源、时间、知识点映射，并遵守版权，不批量复制受保护题库。

十四、数学公式 P0

数学内容内部使用标准 LaTeX/结构化表达，KaTeX 统一渲染。裸 LaTeX、乱码、错误上下标、错误转义、公式裁切均属于发布阻断问题。

测试覆盖极限、积分、求和、分式、根式、矩阵、分段函数、集合、量词、希腊字母、不等式和复杂嵌套。

十五、现代高质量 UI

UI 必须像成熟现代 AI 学习软件，而不是后台管理系统。开发前调研多个活跃、许可证合适的高质量 React UI/设计系统，再确定基础。

主界面：左侧教材知识树与掌握状态；中间沉浸式长文学习页；右侧上下文 AI Tutor；顶部为全局搜索、Workspace、学习状态和通知/更新信箱。

支持亮/暗模式，排版适合长时间阅读；统一间距、圆角、字号和组件层级；数学公式与正文协调；动画克制；避免廉价渐变、卡片堆砌和按钮墙。

移动/窄屏至少保证核心学习页、Tutor 和公式完整可用。

十六、期末个人复习资料与 Word/PDF（正式路线）

系统后续自动生成：个人完整教辅、公式/定理条件速查、弱点本、代表性错题本、题型地图、高频个人错误、专项训练、7 天/3 天/1 天复习计划。

Word/PDF 输出必须保证中文、数学公式、标题层级、表格和分页质量。

十七、像真正软件一样分发

正式发行生成干净 Windows x64 ZIP，例如 CalculusWorkbench-v1.0.0-Windows-x64.zip。

普通用户应做到：下载 → 解压 → 双击启动 → 自动初始化 → 浏览器打开 → 导入教材 → 填自己的 DeepSeek Key。

不得要求普通用户手工 npm install、修改源码或配置数据库。发行包不得包含开发者个人教材、API Key、错题、聊天、日志、数据库或备份。

十八、软件内消息箱 / 更新中心

顶部通知中心承担真正的软件“信息箱”：显示新版本、补丁、重要 Bug 修复、维护报告、数据库迁移提醒和新功能。

更新卡片展示版本号、Patch/Minor/Major 类型、更新内容、风险、数据库影响、测试摘要，并提供立即更新、稍后提醒、查看详情。

重大更新不得静默安装。

十九、增量更新、备份与回滚

第一次安装后原则上不再删除软件重新下载。更新流程：下载更新 → 完整性校验 → 自动备份 → 停止服务 → 安装 Candidate/补丁 →

数据库 migration → 自动测试 → 切换 Stable → 重启。失败必须自动恢复 LAST_KNOWN_GOOD。

更新器与主程序分离。正式版本同时生成完整 ZIP、适用的增量 Patch 和 CHANGELOG。

二十、长期 Maintenance / Development Agent

后台 Agent 长期维护项目，但绝不能未经验证直接修改 Stable。每日检查日志、崩溃、失败任务、慢请求、数据库、DeepSeek API、PDF/视觉解析、

公式渲染和近期代码；在 Candidate 中修复并测试。每周执行完整回归、备份恢复、多 Workspace、目录迁移、教材解析、视觉识别、公式压力、

性能退化和依赖检查。同一问题自动修复最多 3 轮，失败后熔断并保存研究记录。

二十一、版本长期成长

采用语义化版本和 STABLE/CANDIDATE/TESTING/FAILED/ROLLED_BACK 状态。V1 优先把可信教材、深度教学、Tutor、个人闭环、诊断、

漂亮 UI、发行和更新底座做稳；OCR/视觉增强、联网研究、自动出题验题、期末导出等可以随 Minor/Major 版本继续完善。

它们是正式规划功能，不是“明确不做”。

二十二、验收红线

以下任一情况禁止发布：关键数学事实错误；未经核验 AI 内容冒充教材事实；视觉识别结果直接成为 VERIFIED；伪造页码/来源；

关键公式乱码/裁切；证明存在影响理解的关键跳步；知识页只有结论没有教学解释；例题只有步骤没有方法原因；弱点无证据；

DeepSeek 故障导致本地教材不可阅读；更新覆盖用户数据；更新失败无法回滚；发行 ZIP 需要普通用户手工安装开发依赖。

二十三、最终验收

真实完成：导入文字型教材 + 扫描/复杂公式页面 → PDF.js/视觉双通道处理 → 核验事实 → 生成深度知识页 → Reviewer →

Tutor 多轮追问 → 导入课堂转写 → 记录错题 → 形成有证据诊断 → 自动/人工确认练习 → 重启 → 备份恢复 → 移动目录 →

模拟更新成功与失败回滚 → 生成干净发行 ZIP。所有测试必须输出 PASS/FAIL/BLOCKED/UNVERIFIED，不允许伪造 PASS。

二十四、建议交付结构

outputs/CalculusWorkbench/├─ app/├─ runtime/├─ data/├─ config/├─ updates/├─ backups/├─ logs/├─ exports/├─ tests/├─ release/│  ├─ CalculusWorkbench-vX.Y.Z-Windows-x64.zip│  ├─ patches/│  └─ CHANGELOG.md├─ 启动高数学习工作台.bat├─ 更新程序.bat├─ README_使用说明.txt├─ package.json├─ 依赖锁定文件└─ ACCEPTANCE_REPORT.md

二十五、开发 Agent 的最高执行规则

准确性高于自动化。无法确定时进入 NEEDS_VERIFY，而不是猜。

用户原始数据高于代码更新。任何更新不得静默覆盖原教材、转写、错题和学习记录。

Stable 永远保持可用。所有自动修改先进入 Candidate。

详细教学高于表面完整。零基础学生真正能学懂才算通过。

UI 是正式产品质量的一部分，不允许最后临时套一个后台模板。

软件必须可长期维护、可推送补丁、可分发给其他用户，而不是一次性交付。

DeepSeek Vision 设计依据（开发时需重新核对官方文档）：当前官方文档显示 deepseek-flash 支持图像输入，可用于读取截图文字、分析图表等，并支持 Base64、外部 URL 和 Files API。由于模型和 API 会变化，代码必须以可配置 Provider/Model 方式实现，不能把当前型号当成永久事实。
