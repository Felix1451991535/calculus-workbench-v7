# 用户提供的 V7.1 教材知识框架补充规格

高等数学 AI 学习工作台V7.1 教材完整知识化最高优先级指令

Full-Book Knowledge Build · 覆盖 V7 中过度保守的教材核验逻辑

本文件用于纠正开发 Agent 对“核验”的错误理解。它不是要求取消质量控制，而是重新确定系统的首要任务：用户导入的教材必须被尽可能完整、细粒度、连续地转化为可学习的知识框架。核验是后台质量控制机制，不是阻止教材进入知识体系的人工审批门槛。若本文件与 V7 中关于教材进入知识框架的规则发生冲突，以本文件为准。

一、最高原则：先把整本教材真正做成知识体系

用户选择并导入的教材 PDF 是当前 Workspace 的课程主资料和课程结构基准。系统必须主动处理整本教材，而不是只抽取少量“定义、定理、公式”后等待用户逐条确认。

核心目标： 尽可能把教材从开头到结尾的有效教学内容完整吸收、组织、细化并建立关联，形成能够真正用于学习的知识框架。

“教材已经存在的正常内容”默认可以进入教材知识层。只有真正无法可靠读取、明显冲突、公式残缺或语义无法判断的局部内容，才进入 NEEDS_VERIFY。不得把 NEEDS_VERIFY 当成默认状态，更不得要求用户先手工审核整本书才能生成知识框架。

二、禁止把软件做成“教材审核器”

以下实现属于错误方向：导入一本教材后只得到大量候选卡片；绝大多数内容因为“尚未人工确认”而无法进入知识树；知识树只有章、节、几个定义和定理；AI 教辅因为缺少 VERIFIED 标记而拒绝生成；用户必须逐条点击确认才能继续。

这种实现即使非常谨慎，也判定为产品失败。系统的主体是“AI 学习工作台”，不是“人工教材标注平台”。

三、必须执行 Full-Book Knowledge Build

每次首次导入教材后，系统必须启动持久化的整本教材知识化任务。任务允许分阶段、可暂停、可恢复，但最终目标是覆盖全书，而不是只处理用户当前打开的几页。

建议流水线：PDF 保存与哈希 → 页面/视觉解析 → 目录与章节建模 → 全书内容分块 → 教学实体识别 → 细粒度知识点拆分 → 符号与术语表 → 前置/后续依赖 → 定理-证明-例题-习题关联 → 跨页内容合并 → 完整性扫描 → 深度教学页生成 → Reviewer → 知识框架发布。

四、知识框架必须达到“教学颗粒度”

知识树不能停留在教材目录颗粒度。章和节只是导航层；真正用于学习的节点必须进一步拆到学生会实际卡住、需要解释、需要证明、需要训练的粒度。

例如“数列极限”不能只建立“定义、唯一性、有界性、保号性”几个节点。应根据教材实际内容进一步形成类似：

数列的基本概念与表示；数列与函数的联系；数列变化趋势与极限思想；

数列极限的直观意义；ε-N 定义；ε 的含义；N 的含义；“任意 ε”与“存在 N”的逻辑关系；

n>N 的作用；如何从 |x_n-A|<ε 反推 N；如何用定义证明数列极限；

为什么证明中常取 max{N1,N2}；多个条件如何同时满足；

极限唯一性；证明目标；反证思路；为什么选择中点或相关界；

收敛数列有界性；为什么需要处理前面有限项和后面无限项；统一界如何构造；

保号性、保序性及条件；去掉条件后的反例；

子列概念；n_k 与 k 的关系；子列极限与原数列极限；

教材对应例题、证明技巧、典型方法、常见错误、边界情况与后续知识联系。

上述只是颗粒度示例，不得机械套模板。实际节点必须由用户导入教材的内容决定。教材没有的课程范围不能伪装成教材原有内容。

五、教材内容需要尽可能完整吸收

系统必须处理的不只是标题。适用时应识别并关联：正文解释、概念、定义、符号、公式、性质、定理、推论、条件、证明、证明中的关键操作、例题、解题方法、习题、图像/图表、注释、特殊说明、反例、易忽略条件、章节内部引用和前后知识联系。

如果一节教材原本有十几页有效内容，而知识框架最后只留下几个标题和短摘要，即使这些条目全部标记 VERIFIED，也必须判定 FAIL。

六、核验机制重新定义

核验的目的，是发现解析错误和 AI 篡改，而不是让用户替系统重新录入教材。正常、清晰、一致的教材内容可以自动进入教材知识层，同时保留来源锚点和解析置信信息。

只有出现以下情况时才优先进入 NEEDS_VERIFY：

扫描模糊或文字无法可靠识别；

数学公式明显缺失、断裂、乱码或上下标关系无法判断；

PDF.js 文本、视觉模型/OCR 结果明显冲突；

跨页内容边界无法确定，可能把两个不同内容错误拼接；

章节归属、定理条件、符号含义或数学语义确实存在歧义；

系统检测到可能影响数学含义的解析异常。

不得因为“AI 不能证明自己 100% 正确”就把整本教材都设成待核验。质量控制应优先由多通道解析、结构一致性检查、公式检查、上下文检查和抽样审计承担。

七、来源追溯不要绑死精确页码

来源追溯以教材 ID、章/节、知识点、原文片段和上下文锚点为主。内部 PDF 页索引、区域坐标仅在可靠时使用。不能可靠定位时，不允许为了形式完整伪造“第 X 页”。来源追溯服务于用户回看教材，不应成为阻止知识框架生成的障碍。

八、PDF.js + 视觉理解 + OCR 协同

文字型 PDF 优先使用 PDF.js 提取结构化文字；扫描页、复杂公式、函数图像、几何图、复杂排版或文本提取失败时，使用可配置的视觉模型辅助理解，并可接入 OCR 作为额外候选通道。

多通道的目的不是制造更多人工审核工作，而是提高全书完整吸收能力。对于清晰一致的结果，系统应自动继续知识化；只有冲突或低可靠内容才需要人工介入。

九、建立“教材知识层”和“AI 教学层”两层体系

教材知识层负责尽可能忠实地表达教材有什么、教材怎样组织、教材中的数学对象和关系是什么。AI 教学层负责把这些内容讲得比教材更细、更适合当前用户。两层必须关联，但不能混淆来源。

界面至少能够区分：教材内容 / AI 结构整理 / AI 深度解释 / 课堂补充 / 个人易错与学习结论 / 外部研究补充。

十、知识框架完成后必须进行二次深度教学扩展

“知识点已经进入树”不等于完成。系统必须继续为每个重要节点生成可学习的详细知识页。适用时包括：为什么学、前置知识、直觉、严格定义、符号逐项解释、条件必要性、反例、定理、证明目标、证明策略、为什么这样证明、严格证明、隐藏步骤、基础例子、标准例题、每一步为什么、典型变式、常见错误、识别信号、前后联系、课堂补充、个人易错和理解检测。

例如教材只写“收敛数列一定有界”，AI 教学层必须进一步解释：有界限制的是什么；收敛为什么能控制充分靠后的项；前面有限项如何处理；为什么有限多个数可以取统一界；最终怎样构造整体的界；反命题为什么不成立；有哪些典型反例。

十一、隐藏逻辑必须主动展开

教材中的“显然、易得、同理、取……即可”以及证明中突然出现的中点、最大值、最小值、分奇偶、选子列等操作，如果可能成为初学者的理解断点，系统必须主动展开。

解释顺序优先采用：当前要证明什么 → 已知条件有什么 → 当前障碍是什么 → 为什么想到这个操作 → 操作后得到什么 → 如何回到证明目标。禁止只把教材证明换一种措辞。

十二、全书完整性审计

系统必须建立“教材内容完整吸收审计”，但不要伪造不存在的精确统计分母。可检查：页面/内容块是否处理、章节是否有知识节点、定义/定理/公式/证明/例题/习题候选是否建立关联、跨页内容是否断裂、是否存在大量未归属正文、是否存在只有标题没有教学内容的空节点。

重点寻找“孤立内容”：教材中存在但没有进入任何知识点的段落、公式、例题、证明或图像。发现后应自动重新归类或进入异常队列。

十三、知识点 ID 与知识关系

知识点 ID 必须稳定，重新启动或重新生成教辅不能随意改变。知识关系至少支持：belongs_to、prerequisite、next、defines、uses、proves、example_of、exercise_of、confusable_with、derived_from。关系用于 Tutor 检索、错题映射和弱点诊断。

十四、生成策略：完整性优先，但不伪造教材

必须同时满足两个原则：第一，尽可能完整建立教材知识体系；第二，AI 自己新增的教学解释不得冒充教材原文。

因此允许 AI 大胆进行结构整理、教学扩展、补充例子和解释，但 UI 与数据模型必须记录来源类型。教材没有明确支持的 AI 扩展，应标为 AI 教学内容，而不是“教材说”。

十六、开发 Agent 必须执行的最终工作流

导入教材 → 全书解析 → 多通道补全 → 章节结构 → 教学颗粒度拆分 → 全书知识图谱 → 完整性扫描 → 异常局部 NEEDS_VERIFY → 正常教材内容进入知识层 → 对重要知识点生成深度教学页 → Reviewer 检查教学完整性和数学一致性 → 发布到三栏学习 UI → 后续课堂转写、错题、AI 对话持续丰富个人层。

十七、最终验收问题

验收不能问“核验了多少条”，而必须问：

随机打开教材任意一节，系统生成的知识框架是否基本覆盖这一节真正讲授的内容？是否把内容拆到了学生实际需要理解的粒度？是否能从知识树进入足够详细的学习页？是否能看懂定义、符号、条件、证明思路、关键隐藏步骤和基本题型？

如果答案是否定的，即使数据库、状态机、核验按钮和 UI 全部正常，教材知识化功能仍然没有完成。

十八、与 V7 的关系

V7 中关于 DeepSeek/视觉理解、漂亮 UI、个人学习闭环、弱点诊断、联网研究、自动出题、期末 Word/PDF、ZIP 分发、更新信箱、Patch/Minor/Major、备份回滚和长期 Maintenance Agent 的要求继续有效。

本 V7.1 只覆盖并修正一个关键问题：教材内容不再因为过度核验而被挡在知识框架之外。系统必须从“等待人工确认的候选库”转向“完整教材知识化 + 局部异常核验 + 深度教学扩展”。
